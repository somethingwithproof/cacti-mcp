Cacti MCP అనేది [Cacti MCP ప్లగిన్](https://github.com/somethingwithproof/plugin_mcp) సామర్థ్యాలను stdio ద్వారా MCP టూల్స్‌గా అందుబాటులోకి తెచ్చే Python అడాప్టర్. ఈ ప్లగిన్ ఇప్పటికే నేరుగా HTTP ద్వారా MCPని అందిస్తుంది, కాబట్టి మీ క్లయింట్ రిమోట్ సర్వర్‌కు కనెక్ట్ కాగలిగితే దానినే ఉపయోగించండి. ఈ అడాప్టర్ కేవలం stdio ద్వారా మాత్రమే కమ్యూనికేట్ చేయగల క్లయింట్ల కోసం ఉద్దేశించబడింది. ఇది అధికారిక Python MCP SDKని ఉపయోగించి టూల్ కాల్స్‌ను ప్లగిన్ యొక్క HTTPS APIగా (ఎబిలిటీస్ కాంట్రాక్ట్ v2, `/v1/` పాత్‌ల కింద అందించబడుతుంది, కేవలం బేరర్ టోకెన్ మాత్రమే) అనువదిస్తుంది. ప్రామాణీకరణ, అధికార నిర్ధారణ, ధృవీకరణ మరియు అమలు బాధ్యతలు Cacti వద్దే ఉంటాయి.

**స్థితి: అభివృద్ధిలో ఉంది, 1.0 కంటే ముందు.** వెర్షన్ 0.1.0 సహచర [Cacti MCP ప్లగిన్](https://github.com/somethingwithproof/plugin_mcp) ద్వారా కేవలం రీడ్-ఓన్లీ పరికర జాబితా మరియు ఇన్‌స్టాలేషన్ వెర్షన్‌లకు మద్దతు ఇస్తుంది. ఇంకా ట్యాగ్ చేసిన విడుదల ఏదీ లేదు. డాక్టర్ డయాగ్నస్టిక్స్ మరియు మరమ్మతులు భవిష్యత్తులో చేయబోయే పనులు.

## ఇది ఏమి అందిస్తుంది

| ఆపరేషన్ | Cacti MCP ప్లగిన్ అందించే MCP టూల్ |
|---|---|
| టోకెన్ యజమాని చూడగల పరికరాల జాబితా | `cacti-list-devices` |
| అనుమతి ఉన్న ఒక పరికరాన్ని చదవడం | `cacti-get-device` |
| Cacti, ప్లగిన్ మరియు API వెర్షన్‌లను చదవడం | `cacti-get-system-info` |

పేర్లు, వివరణలు మరియు ఇన్‌పుట్ స్కీమాలు Cacti యొక్క అనుమతి-ఆధారిత ఫిల్టర్ చేసిన డిస్కవరీ ప్రతిస్పందన నుండి వస్తాయి. కొత్త Python టూల్ హ్యాండ్లర్‌లను జోడించకుండానే అనుమతి ఉన్న అదనపు రీడ్-ఓన్లీ ప్రొవైడర్లను గుర్తించవచ్చు.

```text
MCP client --stdio--> cacti-mcp --HTTPS--> Cacti MCP plugin
                                           |-- Cacti permissions
                                           |-- ability providers
                                           `-- execution audit
```

## వినియోగ సందర్భాలు

ఒక MCP క్లయింట్‌ను కనెక్ట్ చేసి, దాని ప్రత్యేక వినియోగదారు చూడగల Cacti పరికరాల జాబితాను పొందవచ్చు, అనుమతి ఉన్న ఒక పరికరాన్ని పరిశీలించవచ్చు లేదా వినియోగదారుకు అవసరమైన పరిపాలనా రీల్మ్ ఉంటే ఇన్‌స్టాలేషన్ వెర్షన్‌లను తిరిగి పొందవచ్చు. పేర్లు మరియు ఇన్‌పుట్ స్కీమాలు ప్లగిన్ డిస్కవరీ ప్రతిస్పందన నుండి వస్తాయి కాబట్టి, అడాప్టర్ ప్రతి ప్రొవైడర్‌ను మళ్లీ నిర్వచించదు. రిజిస్ట్రేషన్ నమూనా మరియు ప్రస్తుత పరిమితుల కోసం ప్లగిన్ యొక్క [ఎబిలిటీ రిజిస్ట్రేషన్ నియమాలు](https://github.com/somethingwithproof/plugin_mcp#write-an-ability-plugin-authors) చూడండి.

## ఇది సురక్షితంగా ఎలా ఉంటుంది

- ప్రారంభించడం, టూల్ డిస్కవరీ, కాల్స్ మరియు stdio ఫ్రేమింగ్ కోసం అధికారిక [`mcp` Python SDK](https://github.com/modelcontextprotocol/python-sdk)ని ఉపయోగిస్తుంది.
- కేవలం రీడ్-ఓన్లీ, నాన్-డిస్ట్రక్టివ్ మరియు ఐడెంపొటెంట్ అంశాలుగా ఖచ్చితమైన అనుబంధ సూచనలు ఉన్న సామర్థ్యాలను మాత్రమే అందిస్తుంది. స్కీమాలు మరియు పేర్లు Cacti నుండి వస్తాయి; అడాప్టర్‌లో ఎటువంటి SQL, పరికర ఆధారాలు లేదా మరమ్మతు కమాండ్‌లు ఉండవు.
- కేవలం బేరర్ టోకెన్‌ను మాత్రమే పంపుతుంది: కుకీలు లేవు, CSRF దశ లేదు. ప్లగిన్ ప్రతి అభ్యర్థనపై టోకెన్ చెల్లుబాటును మరియు అనుమతులను మళ్లీ తనిఖీ చేస్తుంది.
- ధృవీకరించబడిన HTTPSను ఉపయోగిస్తుంది, కుకీలను ఎప్పుడూ నిల్వ చేయదు, దారి మళ్లింపులను తిరస్కరిస్తుంది మరియు ప్రాక్సీ ఎన్విరాన్‌మెంట్ వేరియబుల్స్‌ను విస్మరిస్తుంది. HTTP కోసం `--allow-loopback-http` మరియు నేరుగా లూప్‌బ్యాక్ చిరునామా లేదా `localhost` అవసరం.
- API కాల్స్‌ను మొత్తంగా 35 సెకన్లకు, కనెక్ట్ కావడానికి 5 సెకన్లకు, నెట్‌వర్క్ నిష్క్రియతకు 30 సెకన్లకు మరియు ప్రతి ప్రతిస్పందనకు సుమారు 1 MB (1,100,000 బైట్లు) కు పరిమితం చేస్తుంది. అభ్యర్థన బాడీలు 16,384 బైట్లకు పరిమితం చేయబడ్డాయి. ప్రతి క్లయింట్ సెషన్‌కు కాల్స్ వరుసక్రమంలో నిర్వహించబడతాయి.
- టూల్ ఆర్గ్యుమెంట్‌లను పంపడానికి ముందు చివరి డిస్కవరీ నుండి వచ్చిన ఇన్‌పుట్ స్కీమాతో పోల్చి తనిఖీ చేస్తుంది మరియు ఆ ధృవీకరించబడిన జాబితాలోని ఐడీలను మాత్రమే అమలు చేస్తుంది. సరిపోలకపోవడం లేదా సర్వర్ నుండి లోపభూయిష్ట స్కీమా రావడం జరిగితే అది క్రాష్ కాకుండా టూల్ ఎర్రర్‌గా తిరిగి వస్తుంది.
- అమలును స్వయంచాలకంగా మళ్లీ ప్రయత్నించదు. టూల్ ఎర్రర్‌లలో కేవలం HTTP స్థితి, AIP-193 `status` మరియు ErrorInfo `reason` మాత్రమే ఉంటాయి; సర్వర్ సందేశ పాఠ్యం, ప్రతిస్పందన బాడీలు లేదా ఆధారాలు ఎప్పుడూ ఉండవు. Stdout కేవలం MCP సందేశాల కోసం మాత్రమే కేటాయించబడింది.

SDK వెర్షన్ `uv.lock` (`pyproject.toml`లో `mcp>=2.3,<3`) ద్వారా పిన్ చేయబడింది. ఈ అడాప్టర్ stdio ట్రాన్స్‌పోర్ట్‌తో దాని 2.x లో-లెవల్ సర్వర్‌ను ఉపయోగిస్తుంది; ఇది రిమోట్ MCP HTTP ఎండ్‌పాయింట్, OAuth, రిసోర్సులు, ప్రాంప్ట్‌లు, సబ్‌స్క్రిప్షన్‌లు లేదా నేపథ్య పనులను అమలు చేయదు.

[API ఒప్పందం](../../../docs/api.md) మరియు [అమలు ప్రణాళిక](../../../docs/plan.md) చూడండి.

## ఇన్‌స్టాలేషన్ మరియు కమాండ్ లైన్

Python 3.12 లేదా ఆ తర్వాతి వెర్షన్ మరియు [uv](https://docs.astral.sh/uv/) అవసరం.
ఈ రిపోజిటరీ చెక్అవుట్ నుండి:

```console
uv sync --locked
uv run --locked cacti-mcp --help
```

PHP ప్లగిన్‌ను ఇన్‌స్టాల్ చేసి ప్రారంభించండి, ప్రత్యేక Cacti వినియోగదారుకు దాని రీల్మ్‌ను కేటాయించండి మరియు ఆ వినియోగదారు కోసం ప్లగిన్ కన్సోల్‌లో, దాని My MCP Tokens పేజీలో లేదా దాని `tokens.php` కమాండ్‌తో ఒక వ్యక్తిగత యాక్సెస్ టోకెన్‌ను (`cmcp_pat_` తర్వాత 64 లోయర్‌కేస్ హెక్స్ అంకెల ఫార్మాట్) సృష్టించండి. వినియోగదారుకు ఇప్పటికే ఉన్న Cacti రీల్మ్‌లు మరియు పరికర అనుమతులు అలాగే వర్తిస్తాయి.

మీ సీక్రెట్ మేనేజర్ ద్వారా టోకెన్‌ను `CACTI_MCP_TOKEN`గా అందించండి; దానిని ఎప్పుడూ సోర్స్ కంట్రోల్ లేదా కమాండ్ ఆర్గ్యుమెంట్‌లలో చేర్చవద్దు. ఎండ్‌పాయింట్‌ను విడిగా సెట్ చేయండి. ఇది ఎటువంటి ఆధారాలు, క్వెరీ లేదా ఫ్రాగ్మెంట్ లేకుండా `/plugins/mcp/api.php`తో ముగిసే HTTPS URL అయి ఉండాలి:

```console
export CACTI_MCP_ENDPOINT=https://cacti.example.com/cacti/plugins/mcp/api.php
uv run --locked cacti-mcp
```

`--endpoint URL` అనేది `CACTI_MCP_ENDPOINT`కు బదులుగా ఎండ్‌పాయింట్‌ను సెట్ చేస్తుంది.
`--allow-loopback-http` స్థానిక పరీక్షల కోసం `localhost`, `127.0.0.1`, లేదా `::1`కు సాధారణ HTTPని అనుమతిస్తుంది, `--lang LOCALE` అనేది CLI సందేశ స్థానికీకరణను ఓవర్‌రైడ్ చేస్తుంది, మరియు `--version` వెర్షన్‌ను ముద్రిస్తుంది. ఎండ్‌పాయింట్ మరియు `CACTI_MCP_TOKEN` రెండూ లేకపోతే, కమాండ్ వినియోగ లోపంతో నిష్క్రమిస్తుంది.

### స్థానికీకరణ

CLI సహాయం మరియు అడాప్టర్ లోప సందేశాలు ఎటువంటి అదనపు డిపెండెన్సీలు లేకుండా 45 లోకేల్స్‌లో (`en`, `de`, `es`, `fr`, `it`, `pt-BR`, `nl`, `ru`, `uk`, `ja`, `ko`, `zh-CN`, `zh-TW`, `ar`, `hi`, `pl`, `tr`, `sv`, `vi`, `id`, `af-ZA`, `am-ET`, `ar-EG`, `ar-MA`, `fr-MA`, `fr-SN`, `ha-NG`, `ig-NG`, `mg-MG`, `rw-RW`, `so-SO`, `sw-KE`, `xh-ZA`, `yo-NG`, `zu-ZA`, `bn`, `fa`, `he`, `mr`, `ta`, `te`, `th`, `ur`, `ms`, `fil`) అందుబాటులో ఉన్నాయి. లోకేల్ నిర్ధారణ `--lang`, ఆపై `LC_ALL`, `LC_MESSAGES`, మరియు `LANG`లను తనిఖీ చేసి, చివరకు `en`కు తిరిగి వస్తుంది (`C`/`POSIX` మరియు తెలియని ట్యాగ్‌లు కూడా `en`గా నిర్ధారించబడతాయి). MCP టూల్ పేర్లు, స్కీమాలు మరియు విజయవంతమైన JSON టూల్ పేలోడ్‌లపై ప్రభావం ఉండదు; `is_error=True`తో తిరిగి వచ్చే అడాప్టర్ లోప సందేశాలు క్రియాశీల లోకేల్‌ను అనుసరిస్తాయి.

ఈ ప్రక్రియ stdinలో MCP సందేశాల కోసం వేచి ఉంటుంది. సాధారణంగా ఒక MCP క్లయింట్ దీనిని ప్రారంభిస్తుంది.
సాధారణ `mcpServers` కాన్ఫిగరేషన్ ఫార్మాట్‌ను ఆమోదించే క్లయింట్ల కోసం:

```json
{
  "mcpServers": {
    "cacti": {
      "command": "uv",
      "args": ["run", "--locked", "--directory", "/absolute/path/cacti-mcp", "cacti-mcp"]
    }
  }
}
```

సబ్‌ప్రాసెస్‌కు దాని ఎన్విరాన్‌మెంట్ లేదా సీక్రెట్ సదుపాయం ద్వారా `CACTI_MCP_ENDPOINT` మరియు `CACTI_MCP_TOKEN`లను పంపేలా క్లయింట్‌ను కాన్ఫిగర్ చేయండి. ఎన్విరాన్‌మెంట్ వారసత్వం క్లయింట్‌పై ఆధారపడి ఉంటుంది. టోకెన్ కోసం కమాండ్-లైన్ ఫ్లాగ్ లేదు.

విడిగా ఇన్‌స్టాల్ చేయగల Python డిస్ట్రిబ్యూషన్ `cacti-mcp` కన్సోల్ కమాండ్‌ను అందిస్తుంది. చెక్అవుట్‌ను అమలు చేయడానికి PyPI ప్రచురణ అవసరం లేదు. PHP ప్లగిన్‌కు ఎటువంటి Python డిపెండెన్సీ లేదు.

## విడుదలలు

డిస్ట్రిబ్యూషన్ వెర్షన్ [pyproject.toml](../../../pyproject.toml)లో నమోదు చేయబడింది.
ట్యాగ్ చేసిన విడుదలలు అందుబాటులోకి వచ్చే వరకు, సోర్స్ చెక్అవుట్ లేదా విజయవంతమైన [CI రన్](https://github.com/somethingwithproof/cacti-mcp/actions/workflows/ci.yml) నుండి `python-distributions` ఆర్టిఫాక్ట్‌ను ఉపయోగించండి.
ఈ ఆర్టిఫాక్ట్‌లో wheel మరియు సోర్స్ ఆర్కైవ్ ఉంటాయి. ఇన్‌స్టాల్ చేసిన ప్యాకేజీ `cacti-mcp` కమాండ్ మరియు `python -m cacti_mcp` రెండింటినీ అందిస్తుంది; ఇందులో PHP ప్లగిన్ ఉండదు.

## అభివృద్ధి మరియు పరీక్షలు

```console
uv sync --locked
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked pytest
uv build
```

పరీక్షలు HTTP ధృవీకరణ, ఆధారాల ఐసోలేషన్, బేరర్-మాత్రమే అభ్యర్థనలు, పేజింగ్, లోపాల తొలగింపు మరియు ఒక ఫిక్స్చర్ HTTP సర్వర్‌తో నిజమైన SDK క్లయింట్/సర్వర్ సబ్‌ప్రాసెస్ మార్పిడిని కవర్ చేస్తాయి. వీటికి లైవ్ Cacti ఇన్‌స్టాలేషన్ అవసరం లేదు.

ఈ రిపోజిటరీ `src/cacti_mcp/`, pytest, Ruff, uv మరియు Hatchlingలను ఉపయోగిస్తుంది. CI అనేది Python 3.12, 3.13 మరియు 3.14లను పరీక్షిస్తుంది. ఒక ప్రత్యేక ప్యాకేజింగ్ జాబ్ wheel మరియు సోర్స్ ఆర్కైవ్‌ను నిర్మిస్తుంది, చెక్అవుట్ వెలుపల wheelను ఇన్‌స్టాల్ చేస్తుంది మరియు రెండు ఎంట్రీ పాయింట్‌లను స్మోక్-టెస్ట్ చేస్తుంది. డిస్ట్రిబ్యూషన్లు మరియు పరీక్ష ఫలితాలు వర్క్‌ఫ్లో ఆర్టిఫాక్ట్‌లు.

## సహకారం

పుల్ రిక్వెస్ట్‌లు `develop`కు పంపాలి. అడాప్టర్‌ను Python 3.12కు అనుకూలంగా ఉంచండి, ఇప్పటికే ఉన్న Ruff కాన్ఫిగరేషన్ మరియు `src/cacti_mcp/` ప్యాకేజీ లేఅవుట్‌ను అనుసరించండి మరియు stdoutను కేవలం MCP సందేశాల కోసమే కేటాయించి ఉంచండి. మార్చిన ట్రాన్స్‌పోర్ట్ లేదా టూల్ ప్రవర్తన కోసం పరీక్షలను జోడించండి, పైన పేర్కొన్న తనిఖీలను అమలు చేయండి మరియు `git commit -s`తో కమిట్‌లకు సైన్-ఆఫ్ చేయండి. API మార్పులను Cacti MCP ప్లగిన్‌తో సమన్వయం చేసి, [docs/api.md](../../../docs/api.md)ను నవీకరించండి.
