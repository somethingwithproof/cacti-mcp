Cacti MCP представляет собой адаптер на Python, который предоставляет возможности [плагина Cacti MCP](https://github.com/somethingwithproof/plugin_mcp) в виде инструментов MCP поверх stdio. Плагин уже обслуживает MCP напрямую по HTTP, поэтому используйте этот вариант, если ваш клиент может подключаться к удаленному серверу. Данный адаптер предназначен для клиентов, которые работают только через stdio. Он использует официальный Python MCP SDK и преобразует вызовы инструментов в запросы к HTTPS API плагина (контракт возможностей v2, доступный по путям `/v1/`, аутентификация только по bearer-токену).
Cacti отвечает за аутентификацию, авторизацию, валидацию и выполнение.

**Статус: в разработке, до версии 1.0.** Версия 0.1.0 поддерживает инвентаризацию устройств только для чтения и получение версий установки через сопутствующий [плагин Cacti MCP](https://github.com/somethingwithproof/plugin_mcp). Тегированных релизов пока нет. Диагностика и функции восстановления запланированы на будущее.

## Предоставляемые возможности

| Операция | Инструмент MCP, предоставляемый плагином Cacti MCP |
|---|---|
| Список устройств, доступных владельцу токена | `cacti-list-devices` |
| Чтение данных одного разрешенного устройства | `cacti-get-device` |
| Чтение версий Cacti, плагина и API | `cacti-get-system-info` |

Имена, описания и схемы входных параметров поступают из ответа обнаружения Cacti, отфильтрованного по правам доступа. Дополнительные разрешенные провайдеры с доступом только на чтение могут обнаруживаться без добавления новых обработчиков на Python.

```text
MCP client --stdio--> cacti-mcp --HTTPS--> Cacti MCP plugin
                                           |-- Cacti permissions
                                           |-- ability providers
                                           `-- execution audit
```

## Сценарии использования

Подключите клиент MCP, чтобы просматривать список устройств Cacti, доступных выделенному пользователю, получать сведения о конкретном разрешенном устройстве или запрашивать версии установки, если у пользователя есть необходимая административная область прав (realm). Имена и схемы входных параметров поступают из ответа обнаружения плагина, поэтому адаптер не дублирует описание каждого провайдера. Подробности о модели регистрации и текущих ограничениях см. в [правилах регистрации возможностей](https://github.com/somethingwithproof/plugin_mcp#write-an-ability-plugin-authors) плагина.

## Механизмы безопасности

- Использует официальный [Python SDK `mcp`](https://github.com/modelcontextprotocol/python-sdk) для инициализации, обнаружения инструментов, вызовов и кадрирования stdio.
- Предоставляет только те возможности, чьи аннотации строго соответствуют режиму только для чтения, без разрушительных действий и с идемпотентностью. Схемы и имена поступают из Cacti; адаптер не содержит SQL-запросов, учетных данных устройств или команд восстановления.
- Передает только bearer-токен: без cookie и этапа CSRF. Плагин повторно проверяет действительность токена и права доступа при каждом запросе.
- Использует проверяемый HTTPS, никогда не сохраняет cookie, отклоняет перенаправления и игнорирует переменные окружения прокси. Использование HTTP требует флага `--allow-loopback-http` и явного loopback-адреса или `localhost`.
- Ограничивает вызовы API: общее время до 35 секунд, установка соединения до 5 секунд, ожидание сетевой активности до 30 секунд и размер ответа примерно до 1 МБ (1 100 000 байт). Тело запроса ограничено 16 384 байтами. Вызовы в рамках одной клиентской сессии выполняются последовательно.
- Проверяет аргументы инструмента на соответствие входной схеме из последнего обнаружения перед отправкой и выполняет только идентификаторы из этого проверенного каталога. Несоответствие или некорректная схема от сервера возвращаются как ошибка инструмента, а не вызывают аварийное завершение.
- Не выполняет автоматических повторных попыток. Ошибки инструментов содержат только HTTP-статус, поле `status` по AIP-193 и `reason` из ErrorInfo; текст сообщений сервера, тела ответов или учетные данные никогда не передаются. Стандартный вывод (stdout) зарезервирован исключительно для сообщений MCP.

Версия SDK зафиксирована в `uv.lock` (`mcp>=2.3,<3` в `pyproject.toml`). Этот адаптер использует низкоуровневый сервер версии 2.x с транспортом stdio; он не реализует удаленную HTTP-точку MCP, OAuth, ресурсы, промпты, подписки или фоновые задачи.

См. [контракт API](../../../docs/api.md) и [план реализации](../../../docs/plan.md).

## Установка и командная строка

Требуется Python 3.12 или новее и [uv](https://docs.astral.sh/uv/). Из локальной копии этого репозитория:

```console
uv sync --locked
uv run --locked cacti-mcp --help
```

Установите и включите PHP-плагин, назначьте соответствующую область прав выделенному пользователю Cacti и создайте персональный токен доступа для этого пользователя (формат `cmcp_pat_` и 64 шестнадцатеричные цифры в нижнем регистре) в консоли плагина, на странице My MCP Tokens или с помощью команды `tokens.php`. Существующие области прав Cacti и права доступа пользователя к устройствам продолжают действовать.

Передавайте токен через ваш менеджер секретов в переменной `CACTI_MCP_TOKEN`; никогда не добавляйте его в систему контроля версий или аргументы командной строки. Конечную точку задавайте отдельно. Это должен быть HTTPS URL, заканчивающийся на `/plugins/mcp/api.php`, без учетных данных, строки запроса или фрагмента:

```console
export CACTI_MCP_ENDPOINT=https://cacti.example.com/cacti/plugins/mcp/api.php
uv run --locked cacti-mcp
```

Флаг `--endpoint URL` задает конечную точку вместо `CACTI_MCP_ENDPOINT`. Флаг `--allow-loopback-http` разрешает обычный HTTP для `localhost`, `127.0.0.1` или `::1` при локальном тестировании, `--lang LOCALE` переопределяет локализацию сообщений CLI, а `--version` выводит номер версии. Если не заданы одновременно конечная точка и `CACTI_MCP_TOKEN`, команда завершается с ошибкой использования.

### Локализация

Справка CLI и сообщения об ошибках адаптера поставляются на 45 языках (`en`, `de`, `es`, `fr`, `it`, `pt-BR`, `nl`, `ru`, `uk`, `ja`, `ko`, `zh-CN`, `zh-TW`, `ar`, `hi`, `pl`, `tr`, `sv`, `vi`, `id`, `af-ZA`, `am-ET`, `ar-EG`, `ar-MA`, `fr-MA`, `fr-SN`, `ha-NG`, `ig-NG`, `mg-MG`, `rw-RW`, `so-SO`, `sw-KE`, `xh-ZA`, `yo-NG`, `zu-ZA`, `bn`, `fa`, `he`, `mr`, `ta`, `te`, `th`, `ur`, `ms`, `fil`) без дополнительных зависимостей. Определение локали проверяет `--lang`, затем `LC_ALL`, `LC_MESSAGES` и `LANG`, с резервным переходом на `en` (`C`/`POSIX` и неизвестные теги также сводятся к `en`). Имена инструментов MCP, схемы и успешные JSON-ответы инструментов не изменяются; сообщения об ошибках адаптера, возвращаемые с `is_error=True`, используют активную локаль.

Процесс ожидает сообщения MCP на stdin. Обычно его запускает клиент MCP. Для клиентов, поддерживающих распространенный формат конфигурации `mcpServers`:

```json
{
  "mcpServers": {
    "cacti": {
      "command": "uv",
      "args": ["run", "--locked", "--directory", "/absolute/path/cacti-mcp", "cacti-mcp"]
    }
  }
}
```

Настройте клиент так, чтобы он передавал `CACTI_MCP_ENDPOINT` и `CACTI_MCP_TOKEN` в дочерний процесс через окружение или механизм секретов. Наследование окружения зависит от клиента. Флаг командной строки для передачи токена отсутствует.

Отдельно устанавливаемый дистрибутив Python предоставляет консольную команду `cacti-mcp`. Для запуска из локальной копии публикация в PyPI не требуется. PHP-плагин не зависит от Python.

## Релизы

Версия дистрибутива указана в [pyproject.toml](../../../pyproject.toml). Пока тегированные релизы не выпущены, используйте локальную копию репозитория или артефакт `python-distributions` из успешного [запуска CI](https://github.com/somethingwithproof/cacti-mcp/actions/workflows/ci.yml). Артефакт содержит wheel-пакет и архив с исходным кодом. Установленный пакет предоставляет как команду `cacti-mcp`, так и запуск через `python -m cacti_mcp`; он не включает PHP-плагин.

## Разработка и тестирование

```console
uv sync --locked
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked pytest
uv build
```

Тесты охватывают валидацию HTTP, изоляцию учетных данных, запросы только с bearer-токеном, пагинацию, сокрытие ошибок и реальный обмен между клиентом и сервером SDK в дочернем процессе на фоне тестового HTTP-сервера. Работающая установка Cacti для них не требуется.

В репозитории используются структура `src/cacti_mcp/`, pytest, Ruff, uv и Hatchling. В CI тестируются Python 3.12, 3.13 и 3.14. Отдельная задача сборки пакетов формирует wheel и архив с исходниками, устанавливает wheel за пределами каталога репозитория и выполняет дымовое тестирование обеих точек входа. Дистрибутивы и результаты тестов сохраняются как артефакты рабочего процесса.

## Участие в разработке

Pull-запросы направляйте в ветку `develop`. Сохраняйте совместимость адаптера с Python 3.12, придерживайтесь существующей конфигурации Ruff и структуры пакета `src/cacti_mcp/`, а также оставляйте stdout зарезервированным для сообщений MCP. Добавляйте тесты для измененного поведения транспорта или инструментов, запускайте указанные выше проверки и подписывайте коммиты с помощью `git commit -s`. Согласовывайте изменения API с плагином Cacti MCP и обновляйте [docs/api.md](../../../docs/api.md).
